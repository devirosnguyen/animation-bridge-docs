Animation Bridge

A guide to the semi-automatic pipeline: type a prompt in Unity, get the animation on your rigged character in Cascadeur, refine it with AutoPhysics, then send it to 3ds Max or Unity.

Overview

Unity: prompt + rig→ Python Bridge→ MoMask / HY-Motion (Text-to-Motion)→ Blender: retarget to rig→ Cascadeur: edit + AutoPhysics→ FBX → 3ds Max / Unity
  • Semi-automatic: Cascadeur stays open. You run commands from the Commands menu yourself; if the script server is on, jobs load automatically.
  • Every stage communicates through a job folder: C:/AnimationBridgePipeline/jobs/<job_id>/ containing job.json, status.json, raw.bvh, raw.fbx, final.fbx, log.txt.
  • Job states: queued → generating → retargeting → waiting_cascadeur → in_cascadeur → exported, or error.

Installation

1. Text-to-Motion tools

Place these in E:\AnimationBridgeTools\:

  • venv\: Python 3.10, PyTorch CUDA
  • momask\: MoMask source code and HumanML3D models
  • .clip\: CLIP model
  • venv-hymotion\: Python 3.10, PyTorch 2.5.1 CUDA (HY-Motion only)
  • hymotion\: HY-Motion 1.0 source code; hymotion\ckpts\ holds tencent\HY-Motion-1.0 (4.2 GB), Qwen3-8B (16.4 GB) and clip-vit-large-patch14 (1.7 GB)
  • blender-4.2.9-windows-x64\: portable Blender, run headless for retargeting

2. Workspace and Cascadeur commands

pwsh -File install.ps1

The script creates C:/AnimationBridgePipeline/, copies Bridge/ to bridge/, and installs the commands into <Cascadeur>/resources/scripts/python/commands/AnimationBridge. Then choose Reload scripts in Cascadeur, or restart it.

3. Unity

Copy Unity/Assets/AnimationBridge/ into your project's Assets/, then open Tools › Animation Bridge › Prompt To Cascadeur. Under Settings, fill in Workspace root, Python exe and the path to bridge.py.

4. 3ds Max (untested)

Scripting › Run Script › 3dsMax/AnimationBridgeWatcher.ms, then tick “Tự động theo dõi” (auto-watch).

Quick start (5 steps)

  1. In Cascadeur: Commands › MCP › Start script server (once each time you open Cascadeur).
  2. In Unity, in the Prompt To Cascadeur window: drag your character (e.g. Handyman) into the Rig field, choose the TextToMotion source, type an English prompt, set the duration, then click Generate.
  3. Wait about 10–15 seconds. Cascadeur opens the rig template and loads the animation onto the character.
  4. Edit the animation in Cascadeur and turn on AutoPhysics if needed.
  5. Run Commands › AnimationBridge › Bridge › Export Job.
If the script server isn't running, or Cascadeur still has another job open, click Bridge › Load Next Job yourself.

HY-Motion 1.0

HY-Motion 1.0 (Tencent Hunyuan) is a 1B-parameter flow-matching model trained on a much larger motion dataset than MoMask. It follows longer, multi-step prompts better. It runs locally:

  • Its text encoder, Qwen3-8B, needs 16 GB in bf16 and does not fit next to the motion model on a 16 GB GPU. The weights stay in RAM and each layer is moved to the GPU only while it runs. This takes about 35 s per prompt; the motion itself takes about 6 s.
  • Needs about 20 GB of free RAM while encoding.
  • Output: 22 body joints at 30 fps, written as a BVH with the same bone names as MoMask, so retargeting and Cascadeur work the same. Fingers are not animated.
  • The prompt rewriter and duration LLM are not used: write the prompt in English, under 60 words, and set the duration yourself.
  • License: Tencent HY-Motion 1.0 Community License. It does not apply in the EU, the UK or South Korea, and products with more than 1 million monthly active users need a separate license from Tencent.

Set the default model for jobs without a model in bridge_config.json ("t2m_model": "momask" or "hymotion").

Finger motion

MoMask and HY-Motion animate the body only. Fingers are added after retargeting, in two optional layers:

  1. HandPrior (tick Thêm ngón tay). A small model (31 MB, runs on the CPU in a few seconds) that infers finger motion from the body motion: relaxed curls, grips, and an extended index finger when the arm points. It does not read the prompt.
  2. Hand poses. Deliberate poses over a time range, blended in and out over 0.2 s, on top of HandPrior (or of the rig's rest fingers): point, fist, thumbs_up, open, relaxed, grip, pinch. If ranges overlap, the later row wins.
  • Needs a rig whose Humanoid Avatar maps the finger bones, or the generic Humanoid template. The bare-skeleton fallback has no fingers.
  • Only finger bones are written; the body and wrists keep the generated motion.
  • HandPrior (github.com/AIGAnimation/HandPrior) is a preview release with no published license yet: use it for testing and non-commercial work, and ask the authors before shipping.
  • Install: unzip the add-on release hand_motion_generator.zip to E:\AnimationBridgeTools\handprior\. It runs with the HY-Motion venv (torch, scipy).

Writing prompts for MoMask

MoMask is trained on HumanML3D: 22 joints, up to about 9.8 seconds. The model only understands body motion. It knows nothing about objects, machines or stories.

  • Describe movements, not events. Write “the right arm is pulled forward”, not “caught in a machine”.
  • Keep each sentence to 2–3 steps, joined with then in the order they happen.
  • Always say which arm or leg: right / left.
  • Use common verbs such as walks, runs, kicks, reaches, pulls back, struggles, bends over, falls, stumbles, holds the arm.
  • The same prompt with a different seed gives a different motion. Try 2–3 times and keep the best one.
PromptResult
A person's hand got caught in a crushing machineAlmost no movement, because the model doesn't understand it.
a person reaches forward with the right hand, then the right arm is suddenly pulled forward and the person struggles, pulling back hard with the whole bodyGood: reaches out, gets yanked forward, then pulls free.
a person kicks with the right legGood.
Details the model can't produce (e.g. a hand pinned to a machine) are done in Cascadeur: pin the wrist to a point over the stuck frame range, then turn on AutoPhysics.

In Cascadeur

The commands live under Commands › AnimationBridge:

CommandWhat it does
Bridge › Load Next JobOpens the newest job in the waiting_cascadeur state. If rig/cascadeur_template.casc exists, it opens the template and loads the animation; otherwise it imports the whole FBX.
Bridge › Export JobSaves edited.casc and exports final.fbx plus a final.done flag. The Free version can't export FBX yet.
Bridge › Quick Rig Current SceneQuick Rigs the character in the current tab (Center of mass, ready for AutoPhysics). Bones are matched by name automatically: Unity Humanoid (Left_UpperArm), Mixamo, UE and Biped. The scene is not saved, so use File › Save afterwards.
Bridge › Build Humanoid TemplateBuilds the generic Humanoid skeleton with Blender and Quick Rigs it into rig/humanoid/cascadeur_template.casc. See Rig template.
Bridge › Build Rig TemplateBuilds the rig template (Quick Rigging) automatically from rig/*_rig_base.fbx and rig/human_map.json.
Don't press Ctrl+S in a job tab. The tab is opened from the template, so saving overwrites the template. Use Export Job instead.

Rig template (once per character)

A template is the character after Quick Rigging, with a Center of mass ready for AutoPhysics.

  1. Export the rig in its rest pose (LOD0 only): 
    blender -b --factory-startup -P Bridge/text_to_motion/export_rig_base.py -- ^
  <rig.fbx> C:/AnimationBridgePipeline/rig/<Name>_rig_base.fbx
  2. Optional: create rig/human_map.json in the form {"Hips": "<bone name>", ...}. You can copy this map from the human_map entry in any job's job.json. Without it, bones are matched by name.
  3. In Cascadeur run Bridge › Build Rig Template. It does these steps for you: creates rig.qrigcasc → enters Rig Mode → Generate rig → leaves Rig Mode → saves rig/cascadeur_template.casc.

Generic Humanoid template (recommended)

Instead of one template per character, you can edit every job on a single standard skeleton:

  1. In Cascadeur run Bridge › Build Humanoid Template (once). Blender builds a T-pose Humanoid skeleton with a simple mannequin mesh in rig/humanoid/, then the command Quick Rigs it and saves rig/humanoid/cascadeur_template.casc.
  2. Set "template": "humanoid" in bridge_config.json.

Text-to-motion jobs are then retargeted onto this skeleton and opened on the mannequin in Cascadeur. Unity imports the result as a Humanoid clip, so it plays on any Humanoid character with no per-character setup. The File source still uses the character template above.

Cascadeur's Quick Rigging silently drops joints with Unity-style names such as Left_UpperArm, Left_LowerLeg or Left_Toes, so arms and legs come out unmapped. The Bridge commands work around this by renaming joints temporarily while rigging and restoring the original names afterwards. For a character that already has Unity-style names, open it and run Bridge › Quick Rig Current Scene instead of loading rig.qrigcasc by hand.

Doing it by hand (order matters)

  1. Click the Quick rigging tool button. This turns on Rig Mode.
  2. In the QRT window, click ☰ → load the template rig.qrigcasc. Don't use the JSON rig import option.
  3. Click Add rig elements.
  4. Click Generate rig in the left panel. Cascadeur leaves Rig Mode on its own.
  5. File › Save As → C:/AnimationBridgePipeline/rig/cascadeur_template.casc.
Generating outside Rig Mode reports Rig mode several animationInfo and creates nothing. This has crashed Cascadeur before. Also, don't press Ctrl+Z right after Generate.

AutoPhysics

  1. Load the job through the template (see above). The character must have a Center of mass.
  2. Turn on the AutoPhysics button in the timeline toolbar. A green ghost appears: that's the physics-corrected version.
  3. Adjust keyframes until the ghost looks right, then run Export Job.
If you see “Unable to select automatic center of mass”, the scene probably isn't rigged. Load the job through the template, or build the template first.

Back to Unity / 3ds Max

  • Unity: once a job reaches exported, the clip is imported automatically into Assets/AnimationBridge/Imported/ with the rig's Avatar. Click Import to re-import.
  • 3ds Max: the watcher looks for final.done and merges the animation into the scene. Use plain bones for the Max rig, not Biped/CAT.
  • Exporting the same job again makes both sides reload it.

{
  "cascadeur_auto_load": true,
  "cascadeur_server": "http://127.0.0.1:8765",
  "template": "humanoid",
  "retarget_to_rig": true,
  "tools_dir": "E:/AnimationBridgeTools",
  "momask_python": "E:/AnimationBridgeTools/venv/Scripts/python.exe",
  "momask_dir": "E:/AnimationBridgeTools/momask",
  "t2m_model": "momask",
  "hymotion_python": "E:/AnimationBridgeTools/venv-hymotion/Scripts/python.exe",
  "hymotion_dir": "E:/AnimationBridgeTools/hymotion",
  "handprior_dir": "E:/AnimationBridgeTools/handprior/hand_motion_generator",
  "blender_exe": "E:/AnimationBridgeTools/blender-4.2.9-windows-x64/blender.exe"
}
  • cascadeur_auto_load: set to false to stop auto-loading through the script server.
  • template: "humanoid" uses the generic Humanoid template for text-to-motion jobs (falls back to the job's rig if it hasn't been built yet). Leave it out to retarget onto the character from Unity.
  • t2m_model: default text-to-motion model when the job does not name one: momask, hymotion or hymotion_lite.
  • retarget_to_rig: set to false to output the bare MoMask skeleton (22 bones, no mesh) instead of retargeting to the rig.
  • The ANIM_BRIDGE_ROOT environment variable changes the workspace folder Cascadeur uses.

Troubleshooting

SymptomFix
The prompt has no effectThe File source is selected. Switch to TextToMotion.
Cascadeur doesn't load the jobTurn on MCP › Start script server. If an old job is still in_cascadeur, export or delete it, then click Load manually.
The animation barely movesThe prompt is too abstract. Rewrite it following Writing prompts.
The template won't saveThe template file is open in another tab. Close that tab and run the command again.
A job shows errorCheck log.txt in the job folder (Folder button).
Unity doesn't pick up new codeClick into the Unity window so it recompiles.

Current limitations

  • Cascadeur Free can't export FBX. Export Job only saves edited.casc. After upgrading to Indie or Pro, the command exports final.fbx with no code changes.
  • MoMask and HumanML3D are for non-commercial use only.
  • MoMask only understands simple prompts. For better quality, choose HY-Motion 1.0 (see its license notes above).
  • Neither model animates fingers; they come from HandPrior and hand poses (see Finger motion). Fingers cannot be driven by the prompt.
  • The 3ds Max side hasn't been tested yet.
  • AutoPhysics still has to be turned on by hand after a job loads.

Coming soon

Two ways to get FBX without a paid Cascadeur license. Both are planned and not in the current version.

1. MoMask → 3ds Max directly

  • Skips Cascadeur's export step: the MoMask animation (BVH) goes straight into 3ds Max and is retargeted onto the rig with MaxScript.
  • Cascadeur is still used for previewing and hand edits. Edits made in Cascadeur Free can still only be saved as .casc.

2. Animation cleanup in Blender

  • Flow: MoMask → Blender (import BVH, retarget, smooth with a background script) → export final.fbx → Unity / 3ds Max.
  • Blender is free and runs headless, so the whole flow is fully automatic: no app to keep open, no commands to click.
  • The trade-off is no AutoPhysics. For physics or detailed hand edits, use Cascadeur (Indie / Pro).
